## 진행·연결 검사

- 첫 화면에 유형 세 개만 표시하고, 1일형·반일형의 장소 선택은 다음 화면으로 분리했다. 숙박형은 유형 선택 후 바로 버스에서 시작한다.
- 세 유형의 여행을 가상 시계로 실제 DOM에서 끝까지 진행했다. 스테이지 제목·칭찬·해설·클리어·다음 스테이지를 별도 클릭하지 않아도 이어지는지 확인했다.
- 각 장소의 전체 이야기 과제, 이동 중 돌발 퀴즈, 숙소 과제 이후의 숙소 비상 히든 미션을 검사했다.
- 버스 혼합 장면의 정확한 선택 +100·빈 곳 −10·중복 0점, 근접 강조, 형아맨 칭찬·해설 팝업을 확인했다.
- 장소 과제를 마치기 전 배지를 주지 않고, 배지 복습 후 진행하던 여행으로 돌아오는지 검사했다.
- 점프·차례·휴식, 손전등 안전장치, 다른 그림 찾기, 짝맞추기, 같은 그림 찾기, 길 찾기, 위험 구역 피하기, 대피·신고 순서 상태를 검사했다.
- 기존 교사용 연결 자료 25개 유형·장소 조합과 오답 재시도·결과·공유 주소·영상 목록 필터를 검사했다.

## 맥락과 그림 검사

- 1일형·반일형 공원 등의 경로에 휴게소·숙소·숙소 대피가 포함되지 않음을 검사했다.
- 손전등은 숙소 대피, 점프는 스포츠, 위험 구역 피하기는 공원, 정리 전후 비교는 숙소에만 연결하는지 확인했다.
- 영화관 화재와 지진을 별도 상황으로 편성하고, 흔들림 중 몸 보호와 멈춘 뒤 안내에 따른 이동을 구분했다. 공원 돌발 상황은 익수 목격·뱀·벌로 연결했다.
- 버스 실내와 하차 후 야외를 다른 원화로 연결했다. 전용 상황 그림이 없는 문제는 관계없는 장소 그림을 사용하지 않고 행동 도움 AAC임을 명시했다.
- 로고·UI 32종·AAC·장소·위험물·비교 그림·상황 그림을 직접 열어 확인했다. 개별 프롬프트·좌표·검수는 game-art.md, 상황그림_검수.md, room-difference-art.md, brand-identity.md, ui-icons-*.md에 기록했다.

내용의 근거와 장소별 검토표는 통합_교육활동설계.md에 따로 정리했다. 자동 완주 성공만으로 교육 내용이 충분하거나 실제 안전 수행이 검증됐다고 판단하지 않는다.

## 확인 한계

검사는 JSDOM과 가상 시계·상태 로직이다. 최종 브라우저 자동화 도구는 failed to write kernel assets (os error 3)로 초기화되지 않아 실제 최종 렌더링·전체 화면 캡처를 확인하지 못했다. 사용자가 제공한 화면의 크기·전환·그림 불일치는 반영했다. 이전 테마 캡처를 최신 결과로 재사용하지 않았다.

전자칠판·태블릿의 실기기 터치, 실제 음성 재생과 영상 전체 공개 상태·자막·감각 자극, 학생별 이해와 현장 행동은 별도 확인 대상이다. 실제 시설의 경로·피난계획·인솔자와 필요한 지원이 우선이다. 공개 서버 배포 완료 검증은 포함하지 않는다.
