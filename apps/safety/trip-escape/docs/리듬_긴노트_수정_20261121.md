# 멈춰요 긴 노트 입력 수정 · 2026-11-21

화면의 두 경계선 중 오른쪽 선에 머리를 맞춰 눌렀을 때, 실제 판정 위치인 중앙보다 약0.3초 먼저 입력되어 긴 노트가 시작되지 않는 문제를 실제 WAV 재생으로 재현했습니다. 꼬리보다80ms 먼저 놓으면 무조건 실패하는 반면, 놓지 않아도 꼬리가 지나면 자동 성공하는 문제도 확인했습니다. 이전 검사는 중앙 시각의 누름 유지 성공만 확인해 이 차이를 놓쳤습니다.

판정선을 실제 입력 위치의 한 줄로 통일하고 꼬리의 시작·길이를 같은 노트 시계에 맞췄습니다. 이제 머리에서 누르고 꼬리까지 유지한 뒤 실제로 손을 놓을 때 성공 여부를 판정합니다. 끝점의 작은 시간 오차를 허용하며, 짧게 누르거나 너무 일찍 놓기·놓지 않고 계속 누르기는 성공으로 세지 않습니다. 한 노트의 점수는 한 번만 올라갑니다.

터치 스크롤·이미지 끌기·길게 누르기 메뉴가 입력을 가로채지 않도록 게임 입력 영역에서 기본 동작을 막았습니다. 포인터가 영역 밖에서 올라와도 판정합니다. OS의 터치 취소·예기치 않은 캡처 해제·포커스 이탈은 손 떼기 성공으로 처리하지 않고 일시정지하며, 같은 곡 위치와 긴 노트에서 이어갈 수 있습니다.

검증은 다음과 같습니다.

- 자동 검사165개 통과. 실제 down/up, 자동 반복, 영역 밖 release, 터치 취소·재개, 끝점±80ms·너무 이른 떼기·계속 누르기, 네 난이도 전체 노트를 검사했습니다.
- 실제 Edge에서 쉬움·보통·어려움·매우 어려움,390·1024·1440px 화면의 마우스·Space·터치 입력을 확인했습니다. 터치를2px 움직여도 유지됩니다.
- 제공된149.84초 곡을 실제 재생하면서 점프151개와 멈춤22개를 조작하고, 멈춤은 마우스·터치·키보드를 번갈아 사용했습니다. 누른 상태에서는 성공이 늘지 않고 놓을 때만 성공이 늘어나는지 확인했습니다.
- 기본20개 진입 페이지의 캐시 식별자를`20261121.2`로 갱신해 수정한JS·CSS가 함께 로드되도록 했습니다. 음악 파일과 노트표의 시각은 변경하지 않았습니다.

실제 전자칠판·태블릿 하드웨어로 검사한 것은 아닙니다. 터치는 Chromium의 실제 터치 입력 경로로 검증했습니다. 배포 후 공개 홈페이지에서도 같은 입력을 확인합니다.
