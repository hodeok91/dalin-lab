# v2.9 변경·검증 기록 · 2026-11-16

관찰 계단은 두 버튼으로 조작합니다. 오른쪽 **오르기**는 바라보는 방향으로 한 칸, 왼쪽 **방향 전환**은 방향을 바꾸면서 한 칸 올라갑니다. PC는 →/Space와 ←, 터치 화면은 같은 두 버튼을 사용합니다. 시간에 따라 체력이 줄고 정답에서 회복하며, 0 또는 보호 별 없이 잘못된 방향을 선택하면 기록 화면이 됩니다. 계단이 계속 생성되고 20층부터 원하는 때 끝낼 수 있습니다. 빠른 6연속 입력으로 5초 오라와 기본 점수 2배를 얻습니다. 코인·큰 코인·체력 충전·보호 별을 수집합니다. 실제 계단의 속도 경쟁을 권하지 않도록 도입·완료 안내를 구분했습니다.

기존 OX 41문항은 각각 **위험 행동 1곳 + 안전 행동 1곳**을 모두 찾습니다. 첫 대상을 찾았을 때도 해당 행동의 이유를 설명합니다. 신고 정보 찾기 1문항은 위치·상황·도움 3대상을 유지합니다. 스포츠·체험실·남학생 숙소의 준비 활동은 체크리스트 대신 한 장면의 안전 3곳·위험 2곳, 총 5곳을 찾습니다. 세 곳만 찾고 넘어가지 않습니다. 장면과 같은 행동으로 단서 그림을 연결했습니다.

다른 변경은 다음과 같습니다.

- 같은 그림 찾기는 틀린 짝을 1.4초 뒤 덮고 같은 게임에서 계속 시도합니다.
- 리듬의 멈춰요는 점프 버튼/화면/키를 꼬리 끝까지 유지하는 노트입니다. 짧은 탭·미입력은 성공으로 세지 않습니다. 자동 피버가 기본이고 시작 전에 수동 발동을 고를 수 있습니다. 제공된 149.84초 WAV 외의 BGM·효과음·TTS는 플레이 중 억제합니다.
- 도구 분류는 좌우 버튼·방향키·끌어 놓기로 즉시 판단하는 24개 스피드 게임입니다.
- 위험 발견은 위험/안전 그림 두 개가 풀숲에서 올라오는 팝업 게임입니다. 동물을 때리는 표현 대신 위험을 발견해 알립니다.
- 손 씻기는 물로 적시기 → 비누 가져오기 → 6부위 각 5초 실제 문지르기 → 헹굼 → 수건으로 말리기입니다. 키보드 누름 유지 대안도 있습니다.
- 물놀이 장비는 캐릭터의 머리·몸·옷에 직접 놓고 실제 착용 그림 8상태가 바뀝니다.
- 119 연습은 숫자 입력·연결·상담원 3질문·마이크/AAC 응답·안내 기다리기로 진행합니다. 실제 전화나 녹음·음성 업로드는 없습니다. 마이크는 목소리 입력 유무만 확인하고, 신고 내용의 적절성은 교사가 함께 확인합니다.
- 대피 3단계와 탑승 6단계는 그림을 직접 옮기는 순서판입니다. 틀린 순서를 고쳐 완성할 수 있습니다.
- 피버 오라는 캐릭터 뒤와 앞의 애니메이션을 함께 사용해 몸에도 빛이 겹칩니다.
- 장소 카드의 이미지 높이를 통일하고, 모바일 계단의 두 주 조작 버튼이 하단 도움말에 가리지 않도록 조정했습니다.

문항 장면 105개, 선택지 그림판 63개(선택지 126개), 단서 59개, 장소 19개, 독립 찾기 장면 9개 = 255개 참조를 연락판과 원본으로 검토했습니다. 수정 뒤 파일 연결·존재·주요 장면 중복 해시도 검사했습니다.

- 수영장 장면은 수영복·수영모·구명조끼·맨발, 손 씻기는 맨손으로 확인했습니다.

- 새 119 장면은 신고 내용과 동일하게 남성 인솔자 1명·남학생 3명, 모두 4명입니다.
- 한쪽 행동만 있던 24문항은 두 행동이 함께 있는 새 장면으로 제작했습니다. 나머지 17문항은 기존 그림 속의 명확한 안전 행동을 추가 대상으로 삼았습니다.

실제 Edge의 마우스·키보드·터치 입력으로 계단 26층, 일시정지·다시하기, 분류 24개, 장비 세 개 직접 끌기, 119 숫자·AAC 응답, 대피 카드 끌기, 위험 알리기 10회, 여섯 부위 30초 실제 마우스 문지르기를 완료했습니다. 1440×1080·1024×768·390×844 화면을 확인했습니다. 브라우저 기록과 캡처는 별도 갤러리에 보관합니다.

물리적인 전자칠판·태블릿, 실제 교실 마이크로 확인한 결과는 아닙니다. 학생들이 체감하는 난이도와 재미는 수업 시범에서 추가 조정할 수 있습니다. 마이크 음성의 내용 자체를 자동 채점한다고 표시하지 않습니다.

## 배경음악

현재 파일은 **bus.mp3 / rest.mp3 / park.mp3 / museum.mp3 / room.mp3 / escape.mp3 / safety-jump.wav**입니다. 마지막 파일이 제공하신 ‘형아맨의 안전 점프’입니다. MP3의 별도 정식 곡명은 확인되지 않아 파일명을 그대로 적었습니다.

[화면·게임 199개 음악 배정표](배경음악_배정표_v2.9.html)에서 7파일을 듣고 각 화면의 사용할 이름을 입력한 뒤 CSV로 저장할 수 있습니다. 같은 파일을 쓸 곳에는 같은 이름을 적으면 됩니다. 추가 음악이 필요할 만한 화면도 후보 행으로 표시했습니다. 표를 편집하는 것만으로 실제 앱 배경음이 바뀌지는 않습니다.

한 화면의 BGM 한 개만 재생하고 늦게 완료된 재생 요청을 정리합니다. 다른 탭이 소리를 가져가면 이전 탭의 BGM·리듬 곡·읽기를 멈춥니다. 119 마이크 입력과 목소리 연습에는 배경음을 섞지 않습니다. 음악 선택표에 신규 음원을 임의로 제작하거나 지정하지 않았습니다.

안전 내용 참고: [119 신고 안내](https://www.nfsa.go.kr/nfa/safetyinfo/emergencyservice/119emergencydeclaration/), [질병관리청 손 씻기](https://health.kdca.go.kr/healthinfo/biz/health/gnrlzHealthInfo/gnrlzHealthInfo/gnrlzHealthInfoView.do?cntnts_sn=6545).

로컬 수정·ZIP 패키징은 GitHub push나 실제 홈페이지 배포와 별개입니다.

음악 배정 CSV는 실제 브라우저가 만든 Blob의 200행·UTF-8 내용과 입력값을 검증하고 파일도 별도로 저장했습니다. 이 자동화 Edge 환경에서는 다운로드 저장이 취소되어, 브라우저 파일 저장 완료까지 확인했다고 보지 않습니다. 배포본의 직접배정 CSV 파일을 함께 제공합니다.

## 2026-11-21 작업 재개와 업로드 준비

현재 소스로 자동159개를 다시 실행해 모두 통과했습니다. 실제 Edge로 계단26층·재시도, 분류24개, 착용3개 끌기,119·AAC, 대피 순서, 위험 알림10회, 손 씻기30초 문지르기를 재확인했고 JavaScript/HTTP 오류가 없었습니다. 세 준비 장면의5대상과 같은 그림의 오답 후 재시도도 확인했습니다.

리듬 홀드 자동 검사가 음원 탐색 완료 전에 눌러 한 차례 실패했습니다. 재생 준비·탐색 완료·노트 시계 동기화를 기다리도록 검사 코드를 수정한 뒤 실제 포인터 누름 유지로 멈춤1회 성공을 확인했습니다. 판정 기준을 완화하거나 실패를 성공으로 바꾸지 않았습니다.

GitHub 웹 업로드의100파일/25MiB 제한을 확인했습니다. 업로드 후보 중 WAV1개가 웹 파일 크기 제한을 넘지만 Git의100MiB 제한을 넘는 파일은 없습니다. Pages는 기존`main`브랜치 루트 배포 설정을 사용합니다. 이후 절차는 [GitHub 업로드와 배포](GitHub_업로드와배포.md)에 기록했습니다.
