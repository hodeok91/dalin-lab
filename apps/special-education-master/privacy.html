3. 요청하는 Google 권한

  • openid, email: 폰에서 계정을 확인하고 구분합니다.
  • drive.appdata: 이 앱의 전용 Drive 공간에서 동기화 사본·입력 명령·처리 결과·선택 첨부 자료를 읽고 저장합니다. 일반 Drive 전체 파일 목록을 읽는 권한은 요청하지 않습니다.
  • calendar.calendarlist.readonly: PC에서 사용 가능한 캘린더와 접근 권한을 확인합니다.
  • calendar.events: PC에서 선택한 캘린더의 일정을 조회·생성·수정·삭제하고 동기화합니다.

권한 동의 범위와 실제 사용할 캘린더·자료 종류는 구분됩니다. 사용자가 고른 자료와 기능을 위해 권한을 사용합니다. 폰 페이지는 캘린더 API에 직접 접근하는 대신 PC가 보낸 선택 자료를 Drive에서 읽습니다.

4. 저장·공유와 외부 서비스

Google 연결 자료는 Google의 인증·Calendar·Drive 서비스를 거칩니다. 서비스 소개·개인정보처리방침·약관은 GitHub Pages, 폰 정적 화면은 Firebase Hosting에서 제공됩니다. 각 사이트의 접속 정보는 해당 호스팅 제공자의 정책에 따라 처리될 수 있습니다. 현재 폰 공개 페이지에는 광고·방문 분석 스크립트를 추가하지 않았습니다.

앱 제작자의 별도 학생 DB 수집 서버로 원장을 자동 업로드하는 구조를 사용하지 않습니다. 일반 동기화 자료는 본인의 Google 계정에 저장됩니다. 교육기관 계정 관리 정책에 따른 접근 가능성과 Google 자체 처리 정책은 별도로 적용될 수 있습니다.

AI 기능은 별도 선택입니다. 현재 형아맨의 일반 질문은 사용자가 입력한 질문을 보내며, 저장된 Google 일정·명렬·관찰 원장을 자동으로 덧붙이지 않습니다. 다른 AI 작성 화면에서는 사용자가 선택한 교육 자료와 입력 내용을 확인해야 합니다. 급식·날씨 등 외부 조회 기능은 해당 기능 제공자에게 필요한 조회 요청을 보냅니다.

5. Google 사용자 데이터의 이용 제한

Google 연결로 얻은 자료는 사용자가 선택한 조회·편집·동기화 기능 제공에 사용합니다. 광고 개인화, 자료 판매, 범용 AI 모델 학습을 목적으로 사용하지 않습니다. Google API에서 받은 정보의 사용과 다른 서비스로의 전송에는 Google API Services User Data Policy의 제한적 이용 요건을 적용합니다. 문의 처리 시에도 사용자의 학생 원장이나 Google 자료를 임의로 열람하는 것을 전제로 하지 않습니다.

6. 보관 기간과 삭제

PC 기록과 백업은 사용자가 관리합니다. Drive에는 동기화 사본·과거 버전·대기 명령·처리 결과가 남을 수 있으며, 고정 기간 뒤 모두 자동 삭제된다고 보장하지 않습니다. 폰 캐시와 전송 대기 입력은 브라우저에 남아 재접속할 때 사용합니다.

  • PC의 연결 해제: 해당 PC의 로그인 토큰과 연결 상태를 해제합니다. Google의 기존 일정·Drive 사본이나 PC 기록을 모두 삭제하지 않습니다.
  • 폰의 ‘화면 비우기’: 표시 화면과 계정 선택 상태를 비웁니다. 원래 계정의 전송 대기 입력과 캐시가 모두 삭제되는 것은 아닙니다.
  • 접근 권한 철회: Google 계정의 연결 관리에서 앱 연결을 제거할 수 있습니다. 권한 철회와 기존 자료 삭제는 별개입니다.
  • 자료 삭제: PC의 해당 기록·백업 파일, Google Calendar 일정, Google Drive 앱 관리의 앱 데이터, 브라우저 사이트 데이터는 각각 확인해 정리합니다. 사이트 데이터를 지우면 아직 전송하지 않은 폰 입력을 잃을 수 있습니다.
